| Статус | `raw` — справочник признаков, не вердикт по конкретной статье |
| Для кого | три агента корпусного аудита статей |

> **Главный принцип.** Ни один признак ниже не является доказательством авторства.
> Это **красные флаги** для ручного разбора. Детекторы ИИ дают точность около 50–60%
> и систематически ошибаются на не-носителях, переводных текстах и коротких текстах.
> Оценка «похоже на ИИ» — это гипотеза о **процессе** (как текст сделан),
> а не приговор автору.

## Часть 1. Претензии по существу: почему это плохо для читателя

ИИ-признаки неприятны не потому, что «машинные», а потому что ломают чтение.
Ниже — претензии в порядке вреда, а не в порядке частоты.

### 1.1 Ложная уверенность и галлюцинации — высший приоритет

| # | Претензия | Как выглядит | Почему критично |
|---|---|---|---|
| G1 | Выдуманные источники | Правдоподобный автор, журнал, год — которых нет | Уничтожает доверие ко всему тексту |
| G2 | Смещённая атрибуция | Верная цитата, но приписана не тому | Хуже, чем выдумка: выглядит проверяемо |
| G3 | Ложные числа | «около 70%», «более 3000» без источника | Создаёт ложную точность |
| G4 | Несуществующие детали | Топоним, должность, название документа | Ломает историческую достоверность |
| G5 | Слипание событий | Два события разных лет в одном предложении | Проверяемый фактический дефект |
| G6 | Устаревшие данные как текущие | «в настоящее время» о прошлом состоянии | Вводит читателя в заблуждение |
| G7 | Ложная точность из осторожности | «примерно», «около», «в некоторых источниках» без нужды | Размывает ответственность автора |

**Диагностика:** прокси — доля дат/имён статьи, которых нет в её research-досье (см. скрипт).
**Важно:** найденный «вне досье» элемент требует ручной проверки; падежи и опечатки дают ложные срабатывания.

### 1.2 Отсутствие фактуры — второй по важности

| # | Претензия | Как выглядит |
|---|---|---|
| F1 | Обобщения вместо имён | «многие эксперты считают», «исследования показывают» |
| F2 | Абстрактные примеры | «некая компания добилась успеха», без названия и цифр |
| F3 | Примеры-пустышки | Пример есть, но не подтверждает тезис |
| F4 | Нет дат и мест | Событие описано без привязки ко времени и географии |
| F5 | Нет конкретных источников | «по данным СМИ», «как известно» |
| F6 | Пересказ вместо ссылки | Содержание передано, идентифицировать труд нельзя |

**Контрпризнак (сильный):** наличие проверяемых архивных деталей — номеров дел, единиц
хранения, подписей, дат с точностью до дня. Это трудно сымитировать без досье.

### 1.3 Отсутствие авторской позиции

| # | Претензия | Как выглядит |
|---|---|---|
| A1 | Беспристрастная середина | «с одной стороны… с другой стороны», вывод отсутствует |
| A2 | Нет оценки | Автор не говорит, что считает верным и почему |
| A3 | Нейтральность там, где нужна позиция | Для конфессионального исторического текста это дефект жанра |
| A4 | Отсутствие оговорок | Нет «я не уверен», «здесь требуется проверка» |
| A5 | Нет различения «факт / мнение источника / мой вывод» | Читатель не понимает, где чья мысль |

### 1.4 Ритм и абзацность — то, что видно глазом

| # | Претензия | Как выглядит | Метрика |
|---|---|---|---|
| R1 | Однородная длина абзацев | Все абзацы 30–45 слов | CV длины абзаца < 0,55 |
| R2 | Однородная длина предложений | «ровно, как по струнке» | низкий разброс слов/предложение |
| R3 | Абзац из одного предложения как норма | Текст рублен на куски | > 30% абзацев |
| R4 | Абзац-список | Перечисление в обёртке из абзаца | визуально |
| R5 | Лозунговый абзац | «Ключевая цепочка: А — Б — В» | визуально |
| R6 | Дробление подзаголовками | h2 каждые 100–150 слов | сл/h2 < 150 |
| R7 | Пустой «глянцевый» вывод | Красиво и ни о чём, без условий | визуально |
| R8 | Отсутствие связок между абзацами | Абзацы как независимые тезисы | ручной разбор |

### 1.5 Лексика и штампы

| # | Претензия | Примеры |
|---|---|---|
| L1 | Стерильные связки | «важно отметить», «стоит подчеркнуть», «в современном мире», «таким образом», «более того» |
| L2 | Отрицательный параллелизм | «это не просто X, это Y» |
| L3 | Тройки | «быстро, качественно, надёжно» |
| L4 | Синтетическая искренность | «честно говоря», «давайте разберёмся» без нужды |
| L5 | Канцелярит | «осуществляет функцию», «играет ключевую роль» |
| L6 | Избыточная вежливость и хвосты ассистента | «надеюсь, это помогло», «если нужно — уточните» |
| L7 | Англицизмы-кальки | «делает смысл», «адресует вопрос», «влияет на» в неверном смысле |
| L8 | Слова-усилители без функции | «крайне», «действительно», «по-настоящему» |
| L9 | Повтор ключевого слова без причины | одно слово 10 раз на абзац |

**Важно:** L1–L3 — самые **ненадёжные** признаки. Хороший редактор убирает их;
плохой ИИ-текст после редактуры их не содержит, но остаётся пустым по F1–F5.

### 1.6 Структурные дефекты

| # | Претензия |
|---|---|
| S1 | Симметричная схема «введение → 3 тезиса → вывод» независимо от темы |
| S2 | Одинаковый размер всех блоков («ни одного лишнего предложения») |
| S3 | Списки там, где нужен абзац, и абзацы там, где нужен список |
| S4 | Заголовки-лозунги (≤4 слов), не описывающие содержание |
| S5 | Дублирование смысла между «Коротко», лидом и телом |
| S6 | Проекции (summary, quiz, description) вводят факты, которых нет в теле |

### 1.7 Специфика историко-богословского текста

| # | Претензия |
|---|---|
| H1 | Сглаживание жестокости: репрессии описаны абстрактно, без имён и последствий |
| H2 | Ложная симметрия: «обе стороны были по-своему правы» без разбора |
| H3 | Карикатура на оппонента вместо сильной версии его позиции |
| H4 | Proof-texting: стих вырван из контекста для готового вывода |
| H5 | Смешение догмата и адиафоры: спорное подано как обязательное |
| H6 | Апокрифическая цитата или красивый, но непроверенный эпиграф |
| H7 | Модернизация: перенос современных категорий в иную эпоху |
| H8 | Отсутствие историографии: нет упоминания, что вопрос спорный и кто спорил |

## Часть 2. Что НЕ является признаком ИИ (антипаттерны аудита)

Критично для двух других агентов: эти вещи **нельзя** записывать в баги.

| # | Ложный признак | Почему это ошибка |
|---|---|---|
| N1 | Наличие списков и подзаголовков | Нормальная вёрстка; навигация нужна читателю |
| N2 | `**жирный**` внутри текста | Может быть механизмом глоссария (проверять в разметке!) |
| N3 | Бэктики вокруг названий | Осознанная стилизация |
| N4 | Короткое тире в «1 Пет. 5:1–4» | Диапазон, а не тире. **Нарушением не является** |
| N5 | Прямые кавычки в YAML frontmatter | Синтаксис YAML, а не текст для читателя |
| N6 | Идеальная грамматика | Редактор тоже вычитывает |
| N7 | Отсутствие «я» | Исторический текст часто пишется без первого лица |
| N8 | Ровность абзацев в переводе | Перевод сам выравнивает ритм |
| N9 | Короткие абзацы в лонгриде о детях/родителях | Жанр допускает; см. критерии исключений |
| N10 | Отсутствие клише | После редактуры их не будет ни у ИИ, ни у человека |

**Правило:** любой признак сначала проверяется в **исходной разметке**, а не в
рендеренном тексте. Иначе аудит выдаёт ложные находки.

### 3.2 Внешние профессиональные стандарты

| Источник | Что берём |
|---|---|
| Plain Writing Act 2010 / plainlanguage.gov | 1 идея на абзац; предложение в среднем ≤20 слов |
| NIH / FDA / WA State plain language | абзац ≤5–7 строк; ≤6 предложений |
| ISO 24995:2023 (plain language) | понятность, находимость, пригодность |
| «Ководство» §62, §97, §104 (Артемий Лебедев) | ёлочки/лапки, длинное тире, неразрывный пробел |
| Издательские памятки по набору (ГОСТ-практика) | тире ≠ дефис; № вместо #; ёлочки в русском тексте |
| Chicago/Turabian + SBL (через Хартию проекта) | аппарат ссылок, локаторы, издания |

### 3.3 Внешние обзоры признаков ИИ-текста

Сводно по: Antiplagiat (методичка 2025), ADPASS, Skillbox Media, «Полиграф для слов»,
Teletype (детекция LLM), 3SELLER, домен-обзоры редакторов. Общий консенсус совпадает с
разделами 1.2–1.6 выше; расхождения — в надёжности лексических маркеров.
