## 0. Три решения, которые надо зафиксировать до начала прохода

### 0.1 Статьи разные — значит критерий «сколько абзацев» не работает сам по себе

Жанр определяет норму. Каталог вводит **профили**, и пороги берутся по профилю.

| Профиль | Признаки | Пример |
|---|---|---|
| `P1. Историческая монография` | лонгрид, аппарат ссылок, повествование | «Баптисты России», Lawson, Gill |
| `P2. Душепопечительская` | короткие абзацы уместны, прямые обращения | «Подросток за кадром», «взрослый ребёнок» |
| `P3. Экзегетическая` | много цитат Писания, разбор по стихам | «Сердце и дух», «Римлянам 7» |
| `P4. Справочная` | списки и таблицы — основной жанр | «Справочник», «Атлас» |
| `P5. Исследовательская заметка` | черновик, не для читателя | `research/*.md` |

**Определение профиля** — по frontmatter (`section`), по наличию summary-quiz и по
плотности библейских ссылок. Профиль фиксируется в первом столбце матрицы багов.

### 0.2 Лозунговость и мелкие абзацы допустимы — но по правилам

Короткий абзац — инструмент. Он перестаёт быть инструментом, когда становится нормой.
Ниже **условия допустимости**: все должны выполняться одновременно.

| Условие | Смысл |
|---|---|
| `И1. Редкость` | таких абзацев ≤ 12% в статье профиля P1; ≤ 25% в P2 |
| `И2. Функция` | абзац несёт удар/поворот/вывод, а не перечисление и не обрывок мысли |
| `И3. Контраст` | рядом есть развёрнутый абзац ≥ 40 слов (иначе нет ритма, есть рубка) |
| `И4. Не рулит структурой` | абзац не подменяет раздел: между двумя короткими — не менее 2 длинных |
| `И5. Не список в обёртке` | если это перечисление — оно оформляется списком, а не абзацем |

Нарушение любого из И1–И5 — баг. Соблюдение всех — допустимый приём, **не баг**.

### 0.3 Нельзя мерить по рендеренному тексту

`**`, `„“`, прямые кавычки, тире — сначала проверяются в **исходной разметке**.
Иначе получаются ложные находки (проверено: `**` в статьях — механизм глоссария,
прямые кавычки — YAML frontmatter, короткое тире — диапазоны стихов).

## 9. Формат записи бага (единый для трёх агентов)

```text
ID:        <PREFIX>-<блок><номер>, напр. BAST-B01
Профиль:   P1..P5
Статья:    <slug> @ Product main <short-sha>
Критерий:  <ID каталога, напр. B-01>
Измерено:  <число + чем измерено (скрипт/ручная проверка)>
Норма:     <порог по профилю>
Разрыв:    <насколько>
Свидетель: <путь к артефакту или цитата с локатором>
Статус:    raw / candidate / verified-at-anchor
Требует:   <что должен сделать редактор, измеримо>
```

**Правила:**
- один баг = один критерий (не сваливать B-01 и C-01 в одну строку);
- число обязательно, «много» — не аргумент;
- если признак из блока D класса (ненадёжные) — баг не заводится, только заметка;
- если сработал ложный признак (N1–N10) — баг **отзывается** и заносится в антипаттерны.

### 11.1 Уточнения к решению №2 (тиры)

Владелец объёмы не назначает. Значит тир — **не присваивается сверху**, а выводится:

- статья ≥2500 слов — «Опора» (норма для большой темы);
- 1500–2500 — «Основная»;
- 900–1500 — «Мост» (допустимо для узкой подтемы);
- **<900 — требует обоснования**; «супер-маленькая и странная» = дефект D-01.

Критерий не в цифре, а в вопросе: **раскрыт ли вопрос по своей роли**. Если материала
собрано на 10 000 слов, а статья 900 — это D-04 (недоиспользование досье), а не
«маленький жанр».

**Порог CV 0,75** калиброван на этом же корпусе. Независимой базы (5 текстов сильной
русской исторической прозы) нет — порог остаётся условным до калибровки.
