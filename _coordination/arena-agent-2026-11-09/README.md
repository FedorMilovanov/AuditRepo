## Как воспроизвести метрики

```bash
# 1. скачать корпус
gh api "repos/FedorMilovanov/gb-is-my-strength/git/trees/main?recursive=1" \
  --jq '.tree[].path' | grep -E '^src/content/articles/.*\.mdx$' > list.txt
while read -r p; do
  n=$(basename "$p")
  gh api "repos/FedorMilovanov/gb-is-my-strength/contents/$p" \
    --jq .content | base64 -d > "corpus/$n"
done < list.txt

# 2. посчитать
python3 tools/corpus_audit.py corpus --dossier-dir dossiers --tsv data/metrics.tsv
```

## Ключевые результаты (пересчитано по полному корпусу)

- **70 статей, 208 903 слова** (включая 6 legacy-статей Гилла, измеренных по HTML).
- Медианная доля абзацев из одного предложения — **38%**; у **47** статей >30%.
- Распределение **бимодальное**: 8 статей ≤15% (сделаны верно), 36 статей ≥35%.
- Медиана **153 слова на h2** при норме 350–500; **60** статей нарушают.
- `readingTime` не соответствует объёму у **50** из 70.
- **6** статей без h2-каркаса; **5** с прямыми кавычками в теле.
- У Гилла **обратный** дефект: 11 339 слов на 3 заголовка.
- Типографика **чистая**; клише **0**; галлюцинаций **нет** (0 дат из 146 вне досье).

**Вывод:** проблема корпуса — **структура прозы и полнота**, а не «ИИ-клише».
Корпус неоднороден в 5 раз по качеству → решается редактурой, а не переписыванием.

## Запреты

1. Не мерить по рендеренному тексту — только по исходной разметке.
2. Не заводить баг по лексическим клише без второго признака (блок D каталога).
3. Не записывать в баги диапазоны стихов (`5:1–4`) и YAML-кавычки.
4. Не пушить и не править общую `MASTER_BUG_MATRIX.md` параллельно.
5. Не утверждать «написано ИИ» — вердикт только `MIXED / UNPROVEN / TEMPLATE-COMPRESSED`.
