# «Коротко»: нужен ли везде? Проверка числами

| Поле | Значение |
|---|---|
| Agent | arena-agent |
| Date | 2026-11-09 (пересмотрено после вопроса владельца «точно ли везде?») |
| Анкор | Product main `5e2db6f0` |
| Проверено | 70 статей корпуса, финальный HTML, `css/site.css`, `js/reader-preferences-head.js` |

---

## 0. Ответ коротко

**Нет, «везде» — неверно.** Блок обязателен там, где он выполняет функцию:
длинный текст, где читателю нужно решить, читать ли дальше. Там, где статьи нет
или она короткая, блок либо бесполезен, либо становится «Коротко» из 3 пунктов
на 711 слов — то есть имитацией сводки.

Мера: **обязателен >1500 слов, не нужен <900, по решению редактора 900–1500.**

---

## 1. Сначала — исправление моих же цифр

В прошлых отчётах я писал «блок есть у 18 из 70». Это было **неверно**: я считал
только HTML-вариант (`<section class="summary-card">`) и не видел второй —
markdown-ный (`## Коротко`). Пересчёт после исправления инструмента:

| Реализация | Статей | Пунктов | Норма 4–6 |
|---|---:|---|---|
| HTML `summary-card` | **20** | 10 статей по 3 пункта, 10 по 5 | **10 из 20 нарушают** |
| Markdown `## Коротко` | **43** | 4–10, медиана 5 | **0 нарушают** |
| **Нет блока** | **7** | — | — |

**Итого блок есть у 63 из 70.** То есть покрытие вовсе не «18 из 70», как я говорил,
а почти полное. Проблема в другом — см. §2.

---

## 2. Главная проблема: две несовместимые реализации

| | HTML-вариант | Markdown-вариант |
|---|---|---|
| Статей | 20 | 43 |
| Пунктов | 3 или 5 | 4–10 |
| Разметка | `<section class="summary-card"><ol>` | `## Коротко` + нумерованный список |
| Стилизация | фирменная карточка, `data-speakable` | обычный заголовок h2 и список |
| Сворачивание | нет | нет |
| Кто использует | серия «Баптисты» + 8 статей о сердце/церкви | всё остальное |

Это **не косметика**: два вида одного блока означают разный вид на сайте, разную
доступность (`data-speakable` есть только в HTML), разное поведение в печати.

**Вывод 2.1.** Прежде чем спрашивать «где блок нужен», надо ответить «какой блок
мы делаем». Сейчас их два, и это дефект сам по себе (нарушение CQS §0.5
«единый reader experience»).

**Вывод 2.2.** В HTML-варианте **половина статей (10 из 20) имеет 3 пункта**
вместо 4–6. В markdown-варианте нарушений нет. Значит дефект «трёх пунктов» —
это дефект одной серии, а не корпуса.

## 3. Где блок реально оправдан: распределение по объёму

| Объём | Статей | С блоком | Без | Медиана пунктов |
|---|---:|---:|---:|---:|
| < 900 слов | 3 | 3 | 0 | **3** |
| 900–1500 | 12 | 12 | 0 | 5 |
| 1500–2500 | 27 | 27 | 0 | 5 |
| > 2500 | 28 | 21 | **7** | 6 |

Два наблюдения:

1. **У коротких статей блок есть, но дефектный** — 3 пункта. Это ровно
   `dva-sezda-1884` (868 слов), `yuzhnaya-shtunda` (711 слов). Сводка из трёх
   пунктов на 700 слов экономит читателю 2 минуты из 3,5 — то есть почти ничего.
2. **У семи самых крупных статей блока нет вообще** — и это худшая дыра.

### 3.1 Семь статей без блока — все крупные

| Статья | Слов |
|---|---:|
| `steven-lawson-samoobman-i-publichnyy-golos` | **14 515** |
| `dzhon-gill-chast-3-nasledie` | **11 339** |
| `dzhon-gill-chast-2-uchenyi` | 8 209 |
| `dzhon-gill-chast-1-chelovek` | 6 303 |
| `kod-da-vinchi` | 5 011 |
| `vzroslaya-doch-otets-brak-soglasie-granitsy-vlasti` | 4 658 |
| `dzhon-gill-chast-4-ekzeget` | 4 403 |

**Вывод 3.1.** Блок отсутствует именно там, где он нужнее всего: в статье на
14,5 тысяч слов читателю не за что зацепиться в начале. Это приоритет №1,
а не «добавить блок в короткие статьи».

## 4. Ответ на вопрос «точно ли везде?»

### 4.1 Нет. Три режима

| Объём | Решение | Почему |
|---|---|---|
| **> 1500 слов** | **обязателен**, 4–6 пунктов | читателю нужно решить, вкладываться ли в 10–45 минут |
| 900–1500 | по решению редактора | экономия мала, но структура помогает |
| **< 900 слов** | **не нужен** | статья читается за 3 минуты; сводка дороже оригинала |

### 4.2 Отдельный случай: справочники

`dzhon-gill-spravochnik`, атласы, хронологии. Там «Коротко» **противопоказано**:
у справочника нет тезиса, который можно свести к 4 пунктам. Читателю нужна
**навигация по разделам** (оглавление), а не пересказ. Это разные задачи.

### 4.3 Отдельный случай: душепопечительские статьи (P2)

«Подросток за кадром», «Взрослый ребёнок». Читатель часто в состоянии стресса,
читает с телефона. Здесь блок **полезен**, но короткий: 3–4 пункта, не 6.
Формально это ниже нормы 4–6 — предлагаю для P2 зафиксировать 3–4 как норму,
а не гнать к шести.

### 4.4 Итоговая матрица решения

| Профиль | >1500 | 900–1500 | <900 |
|---|---|---|---|
| P1 историческая | 5–6 | 4–5 | не нужен |
| P2 душепопечительская | 4 | 3–4 | не нужен |
| P3 экзегетическая | 4–5 | 4 | не нужен |
| P4 справочник | **оглавление вместо сводки** | то же | то же |

## 7. Про сворачивание: в коде его нет

| Признак | Факт |
|---|---|
| Разметка | `<section>` + `<ol>`, не `<details>` |
| CSS, скрывающий тело | отсутствует |
| JS-хуки раскрытия | отсутствуют (5 файлов упоминают `summary-card`, ни один не управляет) |

**Задумано свёрнутым — реализовано всегда раскрытым.**

### 7.1 Как делать правильно

| Правило | Почему |
|---|---|
| `<details>`/`<summary>`, не CSS-скрытие | работает без JS, доступно с клавиатуры, печатается |
| Текст всегда в HTML | иначе исчезает из парсеров, PDF и `data-speakable` |
| `<details open>` на мобиле | на телефоне сводка — главный элемент входа |
| Не подгружать содержимое JS | ломает TTS и печать |

## 8. Что это меняет в матрице

| Формулировка | Было | Стало |
|---|---|---|
| «Блок отсутствует у 52 статей» | неверно | **отсутствует у 7**, все крупные |
| C-06 «<4 пунктов» | 10 находок | **10** (только HTML-вариант, серия «Баптисты») |
| Покрытие | «18 из 70» | **63 из 70** |
| Новый дефект | — | **две реализации одного блока** (20 HTML + 43 markdown) |

### Строки для матрицы

1. `GBS-SUMMARY-DUAL-IMPLEMENTATION` — два вида блока, разная разметка и доступность.
2. `GBS-SUMMARY-MISSING-ON-LONG-ARTICLES` — 7 статей, все > 4000 слов.
3. `GBS-SUMMARY-UNDERLENGTH` — 10 статей серии «Баптисты», 3 пункта вместо 4–6.
4. `GBS-SUMMARY-NOT-COLLAPSIBLE` — свёрнутость заявлена, в коде отсутствует.

Строку `GBS-SUMMARY-MICROHEADING-READABILITY` (9px, 50 маршрутов) **не дублировать**:
это про размер шрифта, другой дефект. Но 50 маршрутов теперь согласуются:
20 HTML-статей + 43 markdown + legacy-маршруты ≈ сходится.
