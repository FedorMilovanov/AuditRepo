## 1. Короткий ответ на вопрос владельца

**Блок нужен — и для людей, и для поиска. Но польза не в том, что вы предполагаете.**
Ваш основной аргумент («для ИИ-поиска») сейчас даёт **0**. Второй аргумент
(«человеку удобно глянуть и свернуть») даёт больше, но при трёх условиях.

### 2.1 Важное уточнение про сворачивание

В текущем коде **сворачивания нет**. Это видно по трём признакам одновременно:
`<section>` вместо `<details>`, в CSS нет правила, скрывающего тело карточки,
и ни один из пяти JS-файлов, упоминающих `summary-card`, не управляет раскрытием.

Вероятно, вы помните плановое решение, которое не доехало до кода. Это отдельный
факт, который стоит зафиксировать: **задумано свёрнутым — реализовано всегда раскрытым.**

## 3. Про ИИ-поиск: почему текущий эффект нулевой

`llms.txt` на сайте есть (`llmstxt.org`, обновлён 2026-10-24, явно перечисляет
Perplexity, ChatGPT Search, Claude, Grok). Проверка:

| Что | Факт |
|---|---|
| Упоминаний `summary` / «Коротко» в `llms.txt` | **0** |
| Формат записей в `llms.txt` | Title + URL + однострочное описание |
| Значит ли это, что блок вреден | **нет** |

**Вывод 3.1.** `llms.txt` работает с URL и заголовками, а не с содержимым карточек.
Поэтому карточка «Коротко» на индексацию в ИИ-поиске **не влияет никак** —
ни положительно, ни отрицательно. Ожидание «поможет для ИИ» не подтверждается.

**Вывод 3.2.** Но это не значит «убрать». Значит — **переставить приоритет
обоснования**: блок оправдан читателем, а не краулером.

## 4. Про людей: где реальная польза

Блок стоит **первым в теле** — это его сильная сторона. Читатель за 5 секунд
понимает, о чём текст, и решает, читать дальше или нет. Это работает.

Но есть условие, при котором польза обнуляется: **если «Коротко» дублирует лид
и первый абзац**. Тогда это не экономия времени, а повторение того же дважды.

**Проверено (К1) — дублирования нет.** Пересечение значимых слов блока с первым
абзацем:

| Статья | Перекрытие | Пунктов |
|---|---:|---:|
| `podpolnaya-pechat` | 0% | 3 |
| `iniciativnaya-gruppa` | 3% | 3 |
| `noch-na-kure` | 3% | 3 |
| `vsehib-1944` | 6% | 3 |
| `yuzhnaya-shtunda` | 8% | 3 |
| `dva-sezda-1884` | 14% | 3 |
| `goneniya-i-sovest` | 15% | 3 |
| `peterburgskaya-liniya` | 16% | 3 |
| `sovetskaya-noch` | 18% | 3 |

Максимум 18% — то есть блок даёт **другую** информацию, а не пересказ вступления.
Польза реальная, а не декоративная.

### 4.0 Обнаружены ДВЕ разные архитектуры блока

При проверке выяснилось, что блок используется двумя несовместимыми способами:

| Архитектура | Статей | Устройство |
|---|---:|---|
| **A. Сводка + лид** | 9 (серия «Баптисты») | 3 пункта, затем развёрнутый вводный абзац |
| **B. Сводка вместо лида** | 8 («Анатомия падения», «Признаки здоровой церкви» и др.) | 5 пунктов, затем **сразу h2**, вводного абзаца нет |

Обе рабочие, но это **несогласованность серии** (нарушение CQS §0.5 «единый reader
experience»). Нужно выбрать один канон. Рекомендация: архитектура B (5 пунктов +
без отдельного лида) — она компактнее и не дублирует. Тогда 9 статей «Баптистов»
надо привести к 5 пунктам и убрать лид либо оставить лид, но явно объявить двумя
разными типами статьи.

### 4.1 Три условия, при которых блок действительно полезен

| Условие | Что значит | Как проверить |
|---|---|---|
| **К1. Не дублирует лид** | пункты дают факты, а не пересказ вступления | сравнить пересечение слов с первым абзацем |
| **К2. Не вводит новых claims** | всё уже есть в теле (стандарт S17) | сверить каждый пункт с телом |
| **К3. 4–6 пунктов** | 3 пункта — это не сводка, а обрывок | уже измерено |

По К3 сейчас **10 статей из 18 нарушают** — у них по 3 пункта.

## 5. Рекомендация

### 5.1 Блок оставить. Но обоснование сменить

Не «для ИИ-поиска» (эффект 0), а «навигация по длинному тексту для человека».
Это честная и проверяемая польза.

### 5.2 Сворачивание — да, но с оговоркой

Сворачивать **можно и полезно** (текст длинный, карточка занимает место).
Но:

| Правило | Почему |
|---|---|
| Контент должен оставаться в HTML, не подгружаться JS | иначе исчезнет из любого парсера и из печати |
| Использовать `<details>/<summary>` | работает без JS, доступно с клавиатуры, печатается |
| Не `display:none` по умолчанию | скрытый текст хуже индексируется и не виден в PDF |
| Раскрытым по умолчанию на мобиле | на маленьком экране сводка — главный элемент |

**Оптимально:** `<details open>` на мобиле, `<details>` на десктопе.
Текст в DOM всегда, скрытие только визуальное.

### 5.3 Заполнить везде, но по-разному

Ваше решение «должно быть везде» принято. Но объём разный:

| Профиль | Пунктов | Почему |
|---|---|---|
| P1 историческая | 5–6 | длинный текст, много линий |
| P3 экзегетическая | 4–5 | структура по стихам |
| P2 душепопечительская | 4 | короче, читатель в состоянии стресса |
| P4 справочная | **0 или оглавление** | сводка бессмысленна, там структура важнее |

Для справки (`dzhon-gill-spravochnik`, атласы) «Коротко» лучше заменить
на оглавление разделов — это полезнее и не дублирует структуру.

### 6.1 Важно: не дублировать существующую строку

В `MASTER_BUG_MATRIX.md` уже есть `GBS-SUMMARY-MICROHEADING-READABILITY` —
о размере шрифта заголовка «КОРОТКО» (9px, читаемость) на **50 маршрутах**.

Это **другой дефект** (типографика, не наличие). Но фактическое противоречие
надо зафиксировать: матрица говорит о 50 маршрутах с блоком, а в статьях
корпуса блок есть только у 18 из 70. Значит:
- либо 50 маршрутов — это другие разделы (серии, хабы, атласы);
- либо часть статей потеряла блок при миграции.

**Требуется проверка перед заведением строки** — иначе получим строку,
противоречащую соседней в той же матрице.
