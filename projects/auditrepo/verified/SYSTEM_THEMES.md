# System Themes — AuditRepo

Системные темы группируют проявления по общему механизму. `active-work` используется только при наличии строки в MASTER.

## AR-THEME-TRUSTED-STATE — machine-green не равен reviewed truth (`active-work`)

- Проявления: strict history audit принимает regex-classification как terminal disposition; structure gate принимает неоговорённый промежуточный project shape; open issues смешивают evidence и backlog semantics.
- Механизм: validators проверяют синтаксис/распознаваемость состояния, но не всегда требуют durable semantic owner и terminal proof.
- Класс результата: fail-closed admission для рискованных terminal claims, без превращения всех исторических файлов в blocking surface.
- Current row: `AR-ISSUE-LIFECYCLE-001`; history and project-contract manifestations closed in waves 2–3.

## AR-THEME-EVIDENCE-GROWTH — сохранность без admission budget (`active-work`)

- Проявления: ZIP/PATCH, сотни screenshots, exact duplicates и один доминирующий project corpus.
- Механизм: политика правильно запрещает терять raw evidence, но не задаёт durable summary, manifest, size exception и dedup boundary на входе.
- Класс результата: ограничить будущий рост и безопасно дедуплицировать только доказанные копии; не устраивать массовую чистку исторического evidence.
- Current rows: none; admission root closed in wave 4, historical duplicate topology explicitly retained.

## AR-THEME-CURRENCY — event-driven freshness без semantic trigger (`active-work`)

- Проявления: terminal/active matrices остаются привязаны к старым anchors, тогда как релевантные source transactions происходят вне AuditRepo.
- Механизм: правило «HEAD movement не reopen» корректно, но нет компактного владельца semantic-impact classification.
- Класс результата: bounded source-event reconciliation только для затронутых authority surfaces.
- Current row: `AR-PROJECT-CURRENCY-001`.
