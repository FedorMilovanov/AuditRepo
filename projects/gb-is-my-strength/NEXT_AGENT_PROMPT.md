## Before Product work

- choose one current MASTER unit, or an owner-selected optional Work Queue item when no verified repair is being taken;
- read only the historical evidence needed for that selected scope;
- inspect the current Product owner, open PRs and applicable rules directly in `FedorMilovanov/gb-is-my-strength`;
- current-check the selected claim on one exact Product anchor before mutation;
- classify the result using the canonical current-check outcomes in `PROJECT_META.yml`;
- use checks proportionate to the diff and claim.

A historical/raw/suspected row is not repair authority. A Product repair requires a current confirmed problem with a bounded semantic owner.

## AuditRepo update rule

Update AuditRepo only when classification, evidence, selected priority, system understanding, owner decision or closure materially changes.

Do **not** update this file solely to copy:

- latest Product HEAD;
- rollback SHA;
- workflow run IDs;
- artifact digests;
- branch inventory;
- every newly merged independent PR.

## Closing work

Any bounded scope is allowed:

- one small finding;
- a duplicate cluster;
- a route package;
- one systemic root and absorbed symptoms;
- a full verification/repair wave;
- a no-fix owner disposition.

Prefer a compact `verified/CLOSURE_LEDGER.md` entry. Create a separate `reverify/` document only for disputed, systemic, security/live/rights or historically valuable evidence.

## Current optional directions

See [`WORK_QUEUE.md`](./WORK_QUEUE.md) only for optional work. The queue is owner-controlled and may be changed, reordered or left empty; it does not outrank the active MASTER.
