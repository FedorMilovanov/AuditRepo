## 1. Что такое спутники в «Сердце» сейчас

24 материала = **6 ядра + 18 спутников**. Но старыми спутниками они уже не являются.

Коммит `605edee` (2026-07-15), «Книжный каркас»:

> «пилот «Сердце»… главы (римские) с подпунктами-статьями (арабские)»

В `hardTextsSeriesConfig.ts`:

```ts
const HEART_CHAPTERS = [
  { id:'ch1', roman:'I',  title:'Диагноз сердца',    lead:'krajne',
    extras:['idoly','religioznoe','sovest','myslennaya','dorozhki'] },
  { id:'ch2', roman:'II', title:'Сердце на войне',   lead:'rimlyanam',
    extras:['yazyk','telo','sokrovishche','tma','skorb'] },
  { id:'ch3', roman:'III',title:'Перелом и перемена',lead:'novoe',
    extras:['menyaetsya','iskushenie','hranit','strah','svoboda'] },
  { id:'ch4', roman:'IV', title:'Жизнь Духом',       lead:'serdce-duh',
    extras:['odinochku','hrista','osvobozhdennoe'] },
];
```

Восемнадцать бывших спутников стали **полноценными статьями глав 2…N** —
`mark: {kind:'arabic'}`, `parent: ch1…ch4`, `pages[id]` создаётся, маршруты есть.

**Итог: книга 4 главы × 24 статьи. Всё объявлено и подключено.**

## 2. Настоящий дефект: `series.json` отстал от конфига

| Место | Что содержит | Расхождение |
|---|---|---|
| `hardTextsSeriesConfig.ts` | 6 ядра + **18 спутников** = 24 | — |
| `data/series.json` | **6 частей** | **−18 статей** |
| `migration/page-ownership.json` | 112 маршрутов, все `hard-texts` = `astro` | верно |

Восемнадцать статей книги **отсутствуют в `series.json`**, хотя по конфигу они
статьи главы, а не спутники.

Отсюда прямое следствие: **хаб `/hard-texts/` показывает 6 карточек из 24.**

Проверка собранной страницы:

```
статей в хабе hard-texts/index.html: 6
   chto-bibliya-nazyvaet-serdcem      (Пролог)
   krajne-li-isporcheno-serdce        (Глава I · Статья 1)
   rimlyanam-7-veruyushchiy-ili-neveruyushchiy (Глава II · Статья 1)
   novoe-serdce                       (Глава III · Статья 1)
   serdce-i-duh                       (Глава IV · Статья 1)
   serdce-spravochnik                 (Справочник)
```

`HardTextsSeriesMapSection.astro` строит таймлайн из `series.json`, а
`HardTextsCardsSection.astro` — карточки по ядру. **Статьи глав 2…N не выводятся
нигде.**

Против: `genesis6SeriesData.ts` держит своих спутников **в `series.json`**
(`n: "6A"`), и хаб их показывает.

**Правило, вытекающее из практики:** всё, что должно быть видно на хабе,
попадает в `series.json`. Гид §2 п.5 («спутники в series.json не вносятся»)
описывает **старые** спутники; после превращения в статьи главы они обязаны там быть.

### 2.1 Класс дефекта

`GBS-SERIES-JSON-STALE` — **P0**. 18 статей книги недоступны из хаба.

## 3. Открытие: HTML-тени не доходят до прода

Это меняет доверие ко всем прежним замерам «живого слоя».

### 3.1 Как работает сборка

`scripts/copy-legacy-to-dist.js` копирует легаси-HTML поверх `dist/`, **но**:

```js
function shouldSkipLegacyFile(srcAbs, astroRoutes) {
  const route = routeForFile(srcAbs);
  return astroRoutes.has(route);   // маршрут у Astro → легаси НЕ копируется
}
```

Источник `astroRoutes` — `migration/page-ownership.json`.
Проверка: из 53 легаси `index.html` **52 объявлены `astro`**.

**Значит для `/articles/*` и `/hard-texts/` файлы `articles/<slug>/index.html`
и `hard-texts/index.html` в `dist/` НЕ попадают.** Прод отдаёт сборку Astro.

### 3.2 Проверка на собранной странице

`articles/krajne-li-isporcheno-serdce/index.html` (коммитнутая тень):

| Признак | Значение | Что означает |
|---|---|---|
| `data-gbs2-series="hard-texts"` | есть | серия подключена |
| `data-gbs2-part-min="41"`, `total-min="53"` | 41 / 53 | **частичная серия** |
| «Часть 1 из 3» | есть | книга из 4 глав/24 статей не видна |
| ссылок на другие статьи «Сердца» | **3**, все на себя | рельс не ведёт никуда |

`data-gbs2-total-min="53"` при 24 статьях и медиане ~26 минут — невозможно.
Конфиг обещает книгу из 24 статей, страница показывает 3 части.

### 3.3 Что это значит для прежних замеров

| Мой прежний замер | Статус |
|---|---|
| «Живой слой баптистов: 16 379 слов, 39–97 сл/мин» | **сделан на устаревшей тени** — не продукт |
| «Абзацность, CV, h2 — по MDX» | неверно дважды: MDX тоже не продукт |
| «readingTime завышен» | направление верно, **цифры не проверены** |
| «0 из 10 достигли 2 800 слов» | **не проверено** — мерил тень |

**Все замеры «живого слоя» надо пересобрать.** Без `node_modules`
это невозможно — либо `npm ci` + `astro build`, либо читать `Body.astro`
как источник текста.

### 3.4 Новый класс дефекта

`GBS-SHADOW-HTML-STALE` — **P0 по методологии**: коммитнутые HTML-тени
устарели и вводят в заблуждение любого аудитора. Они не попадают в прод,
но выглядят как прод.

### 4.2 Охраны

| Охрана | Что ловит | Строк |
|---|---|---:|
| `G-SERIES-JSON-PARITY` | конфиг серии ≠ `series.json` по составу | ~15 |
| `G-SHADOW-HTML-FRESH` | HTML-тень старше своего `Body.astro` | ~10 |
| `G-HUB-COUNT` | хаб серии ≠ числу статей в конфиге | ~8 |

`G-SERIES-JSON-PARITY` поймала бы `−18` сразу. Именно её отсутствие позволило
дефекту жить с 15 июля по 9 ноября — **почти четыре месяца**.

## 5. Ограничения

1. Сборку не запускал — `node_modules` нет. Вывод о вытеснении легаси —
   по чтению `copy-legacy-to-dist.js` и `page-ownership.json`, не по `dist/`.
2. Не проверял, что именно Astro генерирует для маршрута — читал только тень.
3. Число «3 части» взято из HTML-тени; реальная сборка может отличаться.
4. Не проверял `search-manifest.json` — файла в корне нет.
5. `hardTextsSeriesConfig.ts` читал в объёме 45–620 строк, не целиком 700+.
