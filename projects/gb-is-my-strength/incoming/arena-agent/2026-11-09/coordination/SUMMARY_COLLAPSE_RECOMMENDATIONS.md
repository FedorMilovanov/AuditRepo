| Поле | Значение |

| Статус | **рекомендации**, не реализация. Ждут решения владельца |

---

## 0. В чём задача

Владелец: «оно должно быть складным по новому UI и оно по идее везде должно быть».
Факт: **сворачивания в коде нет.** Блок всегда раскрыт.

Это документ о том, как сделать правильно — чтобы, когда дойдёт до правки,
не изобретать заново и не наступить на известные грабли.

---

## 1. Жёсткое требование: текст не должен исчезать

| Что нельзя | Почему |
|---|---|
| `display:none` на теле карточки | текст выпадает из PDF, из `data-speakable`, из парсеров |
| подгрузка содержимого через JS | ломает TTS, печать, скринридеры, edge-кейсы без JS |
| `hidden` по умолчанию на всём блоке | поиск по странице перестаёт находить пункты |
| рендер пунктов из JSON в рантайме | в исходном HTML пусто; ИИ-краулеры и `view-source` видят дырку |

**Правило:** свёрнутость — это **только визуальное состояние**. Разметка и текст
присутствуют всегда, целиком, в статическом HTML.

---

## 2. Рекомендуемая разметка

```html
<section class="summary-card" aria-labelledby="summary-head">
  <details class="summary-card__details" open>
    <summary class="summary-card__head" id="summary-head">Коротко</summary>
    <ol class="summary-card__body">
      <li class="summary-card__item">…</li>
    </ol>
  </details>
</section>
```

### 2.1 Почему именно так

| Решение | Обоснование |
|---|---|
| `<details>/<summary>` | нативная семантика, работает без JS, клавиатура из коробки, поиск по странице находит свёрнутый текст в Firefox/Chrome |
| `open` в разметке | пользователь видит сводку сразу, сворачивает по желанию — не наоборот |
| `<summary>` вместо `<h2>` | `summary` не ломает outline документа; сейчас `h2.summary-card__head` попадает в оглавление как обычный раздел |
| Сохранить классы `summary-card__*` | не ломать существующий CSS и `reader-preferences-head.js` |
| `aria-labelledby` на секции | связь «регион — заголовок» для скринридера |

### 2.2 Важно: сохранить `data-speakable`

На `<section>` сейчас стоит `data-speakable` — на него завязан `reader-preferences-head.js`
(печать/TTS-контракт). При переходе на `<details>` атрибут **переносить не надо**,
оставить на внешней `<section>`. Проверить, что `findTerminalAnchor` и
`isMeaningfulPrintBlock` продолжают видеть блок — они ищут `.summary-card`.

---

## 3. Поведение по устройствам

| Устройство | Состояние по умолчанию | Почему |
|---|---|---|
| Мобильный (< 768px) | **раскрыт** | сводка — главный элемент входа, экран маленький, читать долго |
| Десктоп | **раскрыт** | экономия клика важнее компактности первого экрана |
| Печать / PDF | **раскрыт принудительно** | `details:not([open]) > *:not(summary) { display: block }` в `@media print` |

**Не делать** свёрнутым по умолчанию — это ухудшит вход для читателя и спрячет
единственный короткий ориентир.

### 3.1 CSS для печати (обязательно)

```css
@media print {
  .summary-card__details > *:not(summary) { display: block !important; }
  .summary-card__details > summary::marker { content: ""; }
}
```

Без этого в PDF уйдёт одна строка «Коротко» без пунктов.

## 4. Сохранение состояния

| Вопрос | Рекомендация |
|---|---|
| Запоминать ли выбор пользователя | **да**, `localStorage`, ключ `gbs.summary.open` |
| Разделять ли по статьям | **нет** — предпочтение глобальное, иначе поведение непредсказуемо |
| Приоритет | явный выбор пользователя > дефолт по устройству |
| Сброс | при очистке `localStorage` возвращается дефолт (раскрыт) |

Запоминание — 10 строк JS, но даёт ощущение «сайт меня помнит». При этом
**без JS всё работает**: просто не запоминается.

## 5. Доступность: чек-лист

- [ ] открывается/закрывается с клавиатуры (Enter, Space) — даёт `<summary>` бесплатно
- [ ] состояние озвучивается (`expanded`/`collapsed`) — даёт нативная семантика
- [ ] фокус видим и не теряется при переключении
- [ ] маркер раскрытия виден и не мельче 12px
- [ ] свёрнутый текст **остаётся** в потоке поиска браузера
- [ ] TTS читает пункты, а не только заголовок
- [ ] `prefers-reduced-motion`: анимация раскрытия отключается
- [ ] контраст заголовка `summary` ≥ 4.5:1 (сейчас у `summary-card__head` 9px — отдельный дефект `GBS-SUMMARY-MICROHEADING-READABILITY`)

---

## 6. Что НЕ рекомендую

| Вариант | Почему нет |
|---|---|
| Аккордеон на JS с `max-height` | не работает без JS, ломает печать, сложнее в поддержке |
| Скрывать весь блок, а не тело | пользователь не узнает, что сводка вообще есть |
| Сворачивать в дефолте на мобиле | сводка — главный вход, её надо показать |
| `aria-expanded` руками на `<div>` | нативный `<details>` делает это сам, ручное — источник рассинхрона |
| Делать сводку ссылкой «показать» | ссылка без JS не работает и портит семантику |

## 7. Порядок внедрения (когда решат)

| Шаг | Действие | Риск |
|---|---|---|
| 1 | Выбрать канон разметки (см. §2), зафиксировать в `CONTENT-QUALITY-STANDARD.md` | низкий |
| 2 | Перевести 20 HTML-статей на `<details>` | низкий |
| 3 | Решить судьбу 43 markdown-статей: конвертировать в HTML-карточку или оставить markdown + отдельный компонент | **средний** — нужна миграция контента |
| 4 | Прогнать проверку печати: PDF должен содержать пункты | средний |
| 5 | Проверить TTS на одной статье | низкий |
| 6 | Добавить блок 7 статьям >4000 слов (сейчас без сводки) | низкий |

Шаг 3 — самый дорогой: 43 статьи с `## Коротко` при смене канона потребуют
переписывания разметки. Поэтому канон надо выбрать **до** начала работ.

## 8. Критерий готовности

| Проверка | Ожидание |
|---|---|
| Подсветка/поиск браузера находит пункты в свёрнутом виде | да |
| PDF содержит пункты | да |
| Работает с отключённым JS | да, кроме запоминания состояния |
| Клавиатура | открыть/закрыть без мыши |
| Скринридер | озвучивает «Коротко, свёрнуто/развёрнуто» |
| TTS | читает пункты |
| В `view-source` | все пункты присутствуют |
