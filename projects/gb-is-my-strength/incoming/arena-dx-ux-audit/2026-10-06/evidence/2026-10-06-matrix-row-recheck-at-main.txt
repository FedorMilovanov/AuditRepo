## 1. `GBS-QUIZ-NEXT-HIDDEN-GILL-V16` — NOT REPRODUCIBLE at this anchor (fix commit identified)

Claim under test: in `@media (max-width:63.99em)`, `[data-gill-v16] .quiz-next{display:none}` hides the "Следующий вопрос"
control until an `.is-visible` class is added, so the control is unreachable on 15 of 23 quiz routes.

Measured after answering question 1 of the quiz on a real page:

```text
/articles/dzhon-gill-chast-2-uchenyi/ 390x844   .quiz-next  display=block visibility=visible opacity=1  rect 277x48 (below fold)
/articles/dzhon-gill-chast-2-uchenyi/ 1440x900  .quiz-next  display=block visibility=visible opacity=1  rect 699x46 (below fold)
/articles/20-antisovetov-pastoru/     390x844   .quiz-next  display=block visibility=visible opacity=1  rect 277x48 (below fold)
```

Operability (scrolled into view, trusted click):

```text
/articles/dzhon-gill-chast-2-uchenyi/ 390: click -> progress «Вопрос 2 из 4»    (advanced)
/articles/20-antisovetov-pastoru/     390: click -> progress «Вопрос 2 из 10»   (advanced)
```

Source/artifact state: `css/floating-cluster.css` contains **zero** `quiz-next` rules; the button is styled by
`src/runtime/article-interactions.css` (`.quiz-launch, .quiz-next { … min-height:46px … }`, and 48px at mobile widths) which
is emitted as `dist/_astro/ReaderActionsRuntime.BcTUkum_.css`. The legacy `.quiz-next-btn{…display:none}` in `css/site.css`
is a **different class** and is not what the runtime creates (`src/runtime/article-quiz.js:74,152` sets
`className = 'quiz-next'`). The removal is commit `2ee584d` (2026-10-04, PR #2167, "scoped Gill quiz ownership"):
`git show 2ee584d -- css/floating-cluster.css` deletes exactly

```diff
-  [data-gill-v16] .quiz-next { … }
-  [data-gill-v16] .quiz-next.is-visible { display: block; }
```

and its message names this finding: "Quiz lane — GBS-QUIZ-NEXT-HIDDEN-GILL-V16 (supersedes #2165): the Gill hide/reveal rules
now target the owner button #glsQuizNext".
Caveat: the "below fold" rects are just the article-flow geometry (the quiz sits far down the page), not a visibility problem.
The row's mobile-CSS mechanism cannot occur at this anchor, so the row is a candidate for `closed-by-fix`.
