Не откатывать #2328, не менять ссылку на `#sec-systematics`; перепроверить ключ и объяснение по тексту, а не по позиции перемешанного варианта.
- **Состояние, ввод и сеть (3–9):** сверены объёмы сохранённых матриц, в том числе AX/клавиатура (37), поиск по статье (10), изменение окна (8), переход к заметке (8), офлайн (5), заметки (4). `N/N` означает зафиксированный ожидаемый исход, часто **воспроизведение дефекта**, не «продукт исправен». AX-снимок не свидетельство работы скринридера. Отрицательный Genesis 6 `:~:text=` без нативного положительного контроля не отделяет ограничение браузера от поведения страницы. Результаты заметок в одной вкладке не заменяют [QNL][qnl] с двумя вкладками.
- **Проекция, PDF, озвучка (10–14):** 38/38 записей проекции, отдельная выборка PDF-отпечатков. В [печатной трассе][pdf] — те же `12 → 13` в 6/6 кликов и 4/4 прямых вызовов, SHA текста первых 12 листов совпадает; контролируемый прогрев 500-го начертания даёт `13 → 13`. - **Источник/история/резюме/палитра (15–26):** восстановлены прежние квитанции. Модифицированный клик с HTTP 200 не равен видимому открытию новой вкладки, `back_forward` не равен BFCache, запись раздела не равна видимому заголовку. Повторённые пути к источнику служат контролями; потери черновика, закрытие слоёв, Replay Recent и маршрут «Продолжить» не один и тот же сбой. Не переносить вывод на другой CSS/DOM или другой HEAD только по названию компонента.

Из корня checkout, Python 3 без дополнительных пакетов:

```sh

python3 "$AUDIT/harness/verify-archive.py"           # без записи файлов

python3 "$AUDIT/harness/verify-archive.py" --restore "$SCRATCH/tree"
# Только после checkout итогового коммита: добавить журналы, harness, PNG и квитанции.
git archive HEAD "$I" | tar -xf - -C "$SCRATCH/tree"
```

`--restore` проверяет ZIP, набор имён и SHA всех членов до записи; не перезаписывает существующий каталог. `commands*.log` — **исторические журналы, не исполняемые shell-скрипты**. Для повторения выбирать шаги сборки/проверки отдельно и выполнять из `$SCRATCH/tree`, чтобы работали исходные пути `.../evidence/...`; отчётные команды Git/PR оставлять историческими. `dist` нужен от Product `9edef94ece…` с пинами как в квитанциях; для этапов 24–27 использовать указанные в журналах два дерева Pagefind 1.5.2 вне `dist`. Для некоторых старых проверок нужны A/B PNG из исходного или нового сценария; наличие одного сохранённого кадра или равных SHA не превращать в два захвата.
