## QNL-01 · После удаления редактор подтверждает обновление пустой библиотеки

**`verified-source` + `verified-production-like-dist` + `verified-browser`.** A оставляет в редакторе новый, ещё не сохранённый текст. B удаляет ту же запись, получает «Запись удалена» и может нажать «Отменить». Ждём, пока список **в A** отразит удаление: в обеих вкладках уже 0 записей, но черновик открыт, «Сохранить заметку» доступна.

- **Действие в A:** нажать «Сохранить заметку». Редактор закрывается, статус **«Заметка обновлена.»**, в обоих хранилищах 0 заметок. [На снимке][empty-shot] одновременно видны пустая библиотека и подтверждение. Это не просто несвежая карточка: введённого текста нет в записи.
- **«Отступление», контроль отмены:** нажать «Отменить» в B. Тот же ID появляется в A и B с текстом **до правки**; скачанный Markdown содержит исходный текст, не черновик A.
- **Гилл II, контроль reload:** не отменять удаление, перезагрузить B и нажать «↓ Markdown». Записи нет, библиотека сообщает «Библиотека пуста.», события загрузки файла нет. Перезагружалась только B; ответ в A сохранился.

**Механизм.** [Событие `storage`][storage-hook] перерисовывает открытый список через [`sync()`][sync], но не меняет [снимок `draft.editing`][editor]. При сохранении [`saveNote()`][save] читает текущий список и заменяет текст там, где совпал ID. Удалённого ID в массиве уже нет. Запись неизменённого массива через [`localStorage.setItem`][storage-write] проходит; UI принимает успех записи массива за успех редактирования элемента. [Undo][undo] возвращает удалённый элемент, не содержимое редактора другой вкладки. Квота и сбой браузерного хранилища не нужны для воспроизведения.

## QNL-02 · Более позднее сохранение старого редактора молча затирает новую версию

**`verified-source` + `verified-production-like-dist` + `verified-browser`.** В A на «Отступлении» открыт редактор исходной заметки и набран черновик. B на Гилле II изменяет тот же ID, сохраняет и получает «Заметка обновлена.». До любых дальнейших действий A текст B уже появился в разметке списка A (список скрыт, пока открыт редактор), прочитан из `gb-reader-notes-v1` и найден в реальных загрузках `gb-moya-biblioteka.md` и `gb-library-backup.json` v3 из B. Редактор A сохраняет свой черновик и не сообщает о конфликте. Теперь сохранить в A: панель закрывается с «Заметка обновлена.», обе вкладки показывают только текст A. Следующая загрузка Markdown из B уже не содержит версии B. ID, дата создания `savedAt` и ссылка этой записи не меняются.

**Механизм.** [Тот же `saveNote()`][save] сверяет только ID и подставляет новый текст, не сравнивая текущую запись с версией на момент открытия. Действия намеренно упорядочены; не требуется угадать момент одновременной записи. Это потеря **уже сохранённой** правки в локальном профиле, а не претензия к отсутствию облачной синхронизации.

**Что даёт резервная копия.** Импортировали те же скачанные байты через «⋯ → Восстановить → Добавить без замены». В существующем профиле текст A остался: [импорт объединяет заметки по ID, оставляя существующую][backup-merge]. В отдельном пустом профиле тем же файлом восстановились ID и текст B. Это ожидаемый [контракт v3][library-v3], не ошибка импорта; заранее скачанная копия помогает извлечь прежний текст, но не откатывает запись с тем же ID на месте. Штатный Markdown показывает текущее сохранённое состояние, не историю и не незаписанный черновик.

## Положительный контроль · Разные заметки и экспорт цитаты

A редактирует свободную заметку. B на [Бытии 6][genesis] выделяет мышью «Кумранские фрагменты», сохраняет цитату и нажимает «Заметка» у её карточки. У второй заметки отличающийся ID, две строки текста, тот же URL, что у цитаты, и `quoteText`. Сохранение A не меняет второй записи и цитаты.

- Фильтр «Заметки» + запрос «уточнить» оставляет на экране **одну** запись. Скачанный `gb-moya-biblioteka.md` содержит **две заметки и цитату**: заголовки, UTF‑8, обе строки связанной заметки, строку «К цитате: …» и точные URL. Это соответствует [контракту полного экспорта][library-v2]: [обработчик][export-hook] передаёт [`exportMarkdown()`][presenter] все записи, не отфильтрованный экран.
- B удаляет отдельную цитату. В A привязанная заметка не пропадает и сохраняет контекст и URL. Повторный Markdown содержит **две заметки**, контекст внутри связанной записи сохранён, отдельной секции «Цитата» уже нет. Сверяли сохранённую ссылку `#main-content:~:text=…`, но не обещаем попадание в видимое выделение по ней (см. контроль этапа 7).

## Приёмка исправления и границы

1. Одно место исправления — редактор/сохранение заметок `GBHighlights`. Если ID удалён, **сохранить введённый текст в открытом редакторе**, объяснить, что запись удалена, и дать явное действие для новой заметки или копирования текста. Не показывать успех и не воскрешать запись молча. Undo удаления по-прежнему восстанавливает именно удалённую запись.
2. Если изменён тот же ID, не отбрасывать черновик и не затирать сохранённый текст без выбора читателя. Принимать по последовательности A открыла → B сохранила → A попыталась сохранить, с проверкой обеих вкладок, reload и содержимого файла. Отдельно проверить разные ID: правка A не должна блокироваться изменением другой записи в B. Не превращать «Добавить без замены» в скрытый overwrite.
3. Не расширять это до повторного исправления QL-03/08 или QN-01/02. После любой обработки конфликта оставаться в том же документе и не сбрасывать ответ; проверить и вход из «Обучения», и кнопку библиотеки. Две ветки потери текста — один кандидат на работу с редактором, не две строки нового MASTER.
