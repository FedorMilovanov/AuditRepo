# Этап 26 · «Продолжить» в поиске теряет сохранённый раздел

- **Проект:** «Господь Бог — Сила Моя». Intake `2026-11-18` UTC, продолжение [этапа 25][f25].
- Audited anchor: Product [`main@9edef94ece08012223c1364bec7ddcd561cf5713`][product], неизменный production-like `dist`. AuditRepo `arena/9713b5a4-auditrepo`, база `fcf2e69b2c1531fe606d9838c811b7d1b1071db0`, [Draft #570][draft]. Только evidence intake; без изменений Product и общих реестров.
- **Статус:** воспроизводится локально в Chromium Headless Shell. Не проверялось на публичном хосте, в обычном Chrome, других движках или через touch. Ширина `390×844` означает узкий viewport с реальной клавиатурой/мышью в автоматизации, не мобильное устройство.

## Что заметит читатель

**Для одной и той же корректно сохранённой позиции два «Продолжить» делают разные вещи.** Главная действительно открывает «Песнь Песней: самый личный труд Гилла». Палитра показывает то же название раздела и процент, но Enter и широкая кнопка «Читать» открывают начало Gill II. Обычно до раздела можно добраться вторым нажатием — на подсказку в статье. После «Скрыть» на главной палитра по-прежнему предлагает «Продолжить», но подсказки уже нет. Из самой Gill II команда может заново загрузить эту же статью и сбросить разобранный ответ квиза, хотя заголовок уже был на экране.

## Воспроизведение и контроли

1. В новом контексте открыть Gill II по `/articles/dzhon-gill-chast-2-uchenyi/`. Через настройки → «Обучение» → «Квиз» дойти до `gill.scholar.canticles`. Дать неверный уверенный ответ, затем Tab → Enter на «Перечитать». Действительный source-link переводит фокус к `#sec-canticles` в **том же** документе. Вердикт, объяснение и source-link остаются прежними.
2. Сдвинуть чтение настоящим колесом так, чтобы верх видимого заголовка перешёл с `400.16/483.17` до `299.16/299.17` px, выше линии измерения `325.2/342`. Дождаться записи `gb:reader-state:v1:gb-strength:/articles/dzhon-gill-chast-2-uchenyi`. Она содержит `sectionId: sec-canticles`, правильный `sectionTitle`, `scrollY: 8105/5630`, `progress: 14/15`, `completed: false`. После ухода из Gill II главная читает ту же запись: только `savedAt` может обновиться. Это **не** случай из [F18][f18], где «Перечитать» оставляет предыдущий `sectionId` на линии чтения.
3. В отдельных чистых контекстах активировать одну из команд ниже. Для cross-document-кейсов палитры после главной открыть «Анатомию падения», ничего не прочитывая в ней. `Ctrl+K` → пустое поле → активный `role=option` из группы «Продолжить». `aria-activedescendant`, `aria-selected` и hit-test указывают на этот пункт; это не строка из [«Недавних запросов»][f25]. Ветка «Скрыть»: перед открытием «Анатомии» нажать «Скрыть» на главной, проверить, что карточка ушла и в прежней записи изменился только `dismissedAt`.

Во всех **18/18** активациях палитры цель — путь статьи без фрагмента; ответ HTML 200, новый `performance.timeOrigin`, `pageshow.persisted=false`, `history.length` +1. Палитра/lock не остаются в новом документе. **14/14** недисмиссированных случаев палитры восстановились вторым кликом. Это не утрата сохранённого места. В «Скрыть» не утверждается, что подпись обещает удаление записи из всех интерфейсов: измерена комбинация доступной команды без адреса раздела и отсутствия подсказки на входе.

**Контроль маршрута.** В основной конфигурации оба URL (`…uchenyi/` и `…uchenyi`) отдают один `index.html`. В трёх дополнительных сценариях каждого запуска при 390 сервер отвечает на путь без слеша HTTP 308 в `…uchenyi/`, не подставляя никаких фрагментов. Главная сохраняет fragment и приземляется на заголовке **2/2**; палитра из «Анатомии» и из Gill II оставляет `Y=0` без hash **4/4**. При старте из текущей Gill II даже одинаковый итоговый **pathname** с новым URL без прежнего hash не сохраняет документ. Это контроль локальной обработки слеша, не заявление о настройках внешнего CDN.

## Где расходится поведение

- [`js/bookmark-engine.js:34–38,89–120,272–274`][be]: нормализует storage path, переносит `sectionId`/`sectionTitle`, берёт последнюю незавершённую запись. В том числе отдаёт запись с `dismissedAt`.
- [`js/search.js:1`][search]: пустой `we()` строит «Продолжить» через `getResumeCandidate()` → `be()`. `be()` выводит `Раздел: …`, но задаёт `article.url = e.path`. `Le()` на Enter использует этот же URL; широкий preview ставит его в `href` кнопки `#cp-read-btn`. Нет отдельного места, где один из этих путей добавляет section hash. Запись названия в историю вторична и не используется перед активацией.
- [`HomeResumeClient.js:94–129,181–185,220–244`][home] использует ту же каноническую запись, фильтрует свежий `dismissedAt`, а `resumeHref()` добавляет `#` + закодированный `sectionId`. [`floating-cluster-controller.js:2711–2745`][toast] подавляет подсказку на сутки при `dismissedAt`, иначе она может вызвать [`restoreSnapshot`][reader] с корректным разделом. Это другой путь, который не создаёт hash при восстановлении.

**Разделение с прежними findings:** [F18][f18] — выбор сохраняемого раздела по reader-line; [F17][f17] — возврат к прежнему разделу через «Мою библиотеку»; [F19][f19] — контраст подписи на главной; [F24][f24] — выход из стека и клавиатурное exact Scripture; [F25][f25] — повтор сохранённой строки истории. Здесь корректный `sectionId` доказан **до** открытия палитры, в тексте пункта и в его актуальном `getResumeCandidate()`. Дефект на превращении bookmark в destination, а не в поисковой выдаче, повреждённом `gb-cp-history`, блокировке Library или неизвестном fragment.

**Критерий закрытия:** при корректном `sectionId` пункт, Enter и «Читать» из другого документа должны за одно действие показать указанный раздел (не только изменить URL). Для той же статьи — не разрушать текущее чтение/разбор ради загрузки собственной обложки; проверить сохранённый канонический путь и локальный переход в документе. Если раздел неизвестен или отсутствует, нужен явный fallback к статье без обещания несуществующего раздела. Отдельно согласовать область «Скрыть»: либо раздел не предлагается, либо явное «Продолжить» по-прежнему переносит к нему без зависимости от погашенной пассивной подсказки. Обязательные негативные контроли — нет записи / completed / устаревший sectionId; здесь их не моделировали.
