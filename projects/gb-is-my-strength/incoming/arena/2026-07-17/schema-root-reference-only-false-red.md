## Claim

The package command `npm run schema:rich-results:audit` audits repository-root legacy HTML as if it were current publication and fails on stale dimensions in a page whose current owner is Astro and whose production `dist` projection is correct.

That makes the root command a current false-red for the Product publication boundary.

  "owner": "astro",

## Mechanism

`schema-rich-results-audit.js --root .` discovers root `*.html` without applying current route ownership/publication status. Therefore reference-only HTML can create findings against a route now owned and generated by `src/pages`.

The release checks correctly use `schema:rich-results:audit:dist`, so no current live structured-data regression or release blocker is claimed. The defect is the misleading root audit boundary and its false-red result.

Choose one explicit contract:

1. make the root audit ownership-aware and skip `reference-only`/non-owner HTML when a production Astro owner exists; or
2. rename/reframe the root command as a legacy/reference audit and ensure it cannot be interpreted as current publication health; or
3. if reference-only HTML is intentionally required to remain semantically current, document that authority and repair the stale copy, while retaining a guard that distinguishes source-reference health from production health.

Before promotion to MASTER, verify the intended owner contract in the relevant audit documentation/tests. If root legacy parity is explicitly authoritative, classify this report as `invalid-as-false-red` and instead consider the stale reference copy as bounded maintenance work. Do not classify the live Krajne page as defective.
