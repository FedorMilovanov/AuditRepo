# W12F.1 — scene readiness and homestead collision parity

## Scope / root causes
- Previous main SHA `5458b9f` passed HOREB 6/6 yet had two uncovered P1 bugs. The homestead renderer used `THREE.DodecahedronGeometry(1,1)` rotated in 3 axes while gameplay used a `0.78*sx/sz` ellipse that missed **above-ground** visible facets for all 49 collision-listed rocks. A trusted navigation test had checked only stone centres. Do not confuse this with the previously fixed separate Midian well collision.
- Nile Explorer exposed an enabled button before asynchronous `import('../engine/NilePrelude')` and unconditionally did `setExploring(true)` even if `controller.current` was null. The later-created engine stayed in mode `shot`; a failed import left a confusing fullscreen panel. Recreating the engine on `reducedMotion` also broke UI-engine exploration parity.
- MidianCanvas had analogous remount state staleness after `reducedMotion` or a world change, despite its initial loading button already being disabled.

## Fix
- Homestead: radius `max(sx,sy,sz)` conservatively encloses the actual radius-one dodecahedron after arbitrary Euler rotation; visitor clearance of .12m. Use footprint-aware selection for *all* stones intersecting walkable rectangle, including edge rocks. Original **all 64 rendered stones remain stationary**, no additional mesh/material/texture/draw call, no new imaginary props. Physics boundaries are deliberately wider and require fresh real-walk acceptance.
- Source regression: instantiate `new THREE.DodecahedronGeometry(1,1)` and transform **all** actual vertex attributes by the exact anisotropic scale and XYZ Euler used for rendering; compare projected distances with the very same exported collider radius. Require matching collider indices, entire central approach passable and mobile starting point passable. Original 160 tests expected to become 161.
- Nile: explicit `ready` gate and disabled Explore/cinematic view actions until scene creation is successful; no fullscreen state changes without a valid controller. An engine reload preserves current Explore only for reduced-motion updates and resets navigation on different scene moments. On failure exit fullscreen and show existing text fallback, never stay stuck.
- Midian Canvas: same reset-on-world/synchronize-on-reducedMotion approach, and reset stale `ready/failed` between loads. Preserve focus-return controls and existing hotkeys.
- Browser Nile asserts that when `data-nileRendered` reports actual WebGL complete the Explore button is enabled. A separate delayed-import/early-click browser race case remains useful; do not claim this one assertion alone tests the race.
