## Гипотеза и реальный результат

У v1.0 оба Vite-проекта используют правильные отдельные CSS/JS-ресурсы, но главный JS остаётся тяжёлым. В v1.1 отобраны **необязательные** функции, безопасно откладываемые до взаимодействия: Atlas modal, Atlas quiz, Reader MobileIndex.

Atlas main JS: **504,76 → 477,87 KB**, gzip **144,51 → 138,75 KB**. Модуль modal: 17,86 KB / 5,39 KB gzip; quiz: 12,97 KB / 4,97 KB gzip. Для Quiz `IntersectionObserver rootMargin=1600px` создаёт ранний предзапрос при приближении. Досье загружается при первом обращении.

Reader main JS: **515,51 → 513,60 KB**, gzip **161,62 → 161,77 KB** (то есть сжатый стартовый объём *вырос*). MobileIndex: 4,38 KB / 1,81 KB gzip, загружается только `inArticle`. Решение остаётся экспериментом до профиля слабых сетей; нельзя писать, что быстрее, только что условная доставка функционально работает.

Ошибка, которую обнаружили в процессе: `React.lazy` без ErrorBoundary мог обрушить всё приложение при потере динамического JS-чанка. В обоих проектах теперь есть компонентная граница восстановления. Сбой любого из трёх опциональных модулей сохраняет основную статью и предлагает явное обновление страницы. Патч не включает скрытого `retry`-цикла, который мог бы бесконечно расходовать трафик.
