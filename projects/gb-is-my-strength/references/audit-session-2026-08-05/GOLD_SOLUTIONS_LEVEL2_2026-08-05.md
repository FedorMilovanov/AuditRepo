## 1. ЗОЛОТОЕ РЕШЕНИЕ #1 — AST-конвейер вместо DOM-скрейпа (единый источник для HTML/TTS/search/print)

### Проблема (подтверждена)
- TTS-контроллер читает текст через `querySelector`/`textContent` (`floating-cluster-controller.js:76-77,192`) — **DOM-скрейп**.
- `unified/remark/rehype` **не установлены** (0 в package.json) — контент `.mdx` не превращается в дерево.
- Следствия: TTS может озвучить скрытый текст сноски, search индексирует HTML-артефакты, print дублирует.

### Решение (не «ещё тест», а архитектура)
1. На этапе сборки Astro: `remark` парсит каждый `.mdx` в **AST** (MarkdownAST).
2. Из одного AST генерируются **3 проекции**:
   - `AST → HTML` (существующий рендер);
   - `AST → SSML/plain-text` (для TTS — диктор получает только видимый текст, без сносок-спойлеров);
   - `AST → search-blocks` (для Pagefind — чистый текст по секциям).
3. Проекции сохраняются в `data/projections/*.json` (по SHA контента) → **TTS и search читают проекции, а не DOM**.
4. Mutation-тест: «в сноске есть текст» → TTS-проекция НЕ содержит его; «в h2 есть id» → search-проекция содержит.

**Почему это «золото»:** закрывает класс «озвучка читает скрытое», «search находит артефакты», «print дублирует сноски» одним источником. Плюс снимает DOM-скрейп с TTS (меньше гонок). Это не новый фреймворк, а расширение уже существующего Astro-MDX (оно уже рендерит из `.mdx` — просто не сохраняет промежуточное дерево).

### Риски внедрения (честно)
- Нужно аккуратно: `.mdx` сейчас рендерится Astro-плагином; добавить remark-плагин, который на `build` пишет JSON-проекции. Не трогать рантайм.
- Объём: ~2 файла плагинов + 1 манифест. Не 100 файлов.

## 2. ЗОЛОТОЕ РЕШЕНИЕ #2 — State-машина для floating-cluster (против гонок)

### Проблема (подтверждена)
- `floating-cluster-controller.js` — **17 setTimeout**, ручных флагов `isOpen/isPlaying` — **0**. Всё на императивных проверках.
- Это ровно источник багов «тултип завис», «двойной speak», «фантомный клик» (исторические #680-гонки).

### Решение (не XState-фреймворк, а свой мини-FSM)
1. Завести **один объект-автомат** для плеера:
```js
const player = fsm({
  idle:    { play: 'loading' },
  loading: { ready: 'playing', fail: 'idle' },
  playing: { pause: 'paused', stop: 'idle', end: 'idle' },
  paused:  { resume: 'playing', stop: 'idle' },
});
```
2. Все переходы — через `player.transition(event)`, запрещённые — no-op (не «если... то», а таблица).
3. Таймеры живут в переходах, чистятся при `stop`/`unmount` (решает QUAL-P1-06 «58 таймеров без cleanup»).
4. Тест-генерация: обход графа состояний = исчерпывающий набор кликов (не миллионы тестов, а ~10 состояний × переходы).

**Почему «золото»:** убивает класс «гонки UI» (хистори: #680, D-23 двойной speak, long-press) без фреймворка. 17 setTimeout превращаются в детерминированные переходы.

## 4. ЗОЛОТОЕ РЕШЕНИЕ #4 — Детектор мёртвых фич (CSS/JS без разметки)

### Проблема (подтверждена)
- `#hScriptureBg` — JS-генератор жив, CSS жив, **разметки нет** → фича мертва молча.
- `h-mobile-dock` (13 классов) — CSS есть, разметки нет.
- `enhanceGillMobileBarMarkup` — мёртвый shim.

### Решение `scripts/dead-surface-scan.mjs` (~60 строк)
1. Собрать все `id="..."` и `class="..."` из `src/pages/**`, `src/components/**`.
2. Собрать все селекторы из `css/*.css` и `js/*.js` (`#hScriptureBg`, `.h-mobile-dock*`).
3. Выдать:
   - `CSS_SELECTOR_WITHOUT_MARKUP` (мёртвый CSS);
   - `JS_GETELEMENTBYID_WITHOUT_ID` (мёртвый JS-хук);
   - `CLASS_IN_LEGACY_NOT_IN_ASTRO` (неперенесённые классы).
4. Раз в неделю в CI (schedule) + отчёт в AuditRepo.

**Почему «золото»:** ловит «фичи умерли молча» — класс ошибок, который мы уже дважды нашли вручную (#hScriptureBg, h-mobile-dock), но который иначе не виден.

## 5. ЗОЛОТОЕ РЕШЕНИЕ #5 — CI-«маршрутизатор» вместо разрастания workflow (49 воркфлоу)

### Проблема (подтверждена)
- 49 workflow, многие дублируют setup/build; CI-WORKFLOW-PROLIFERATION открыт; марафон-план §8 предлагает Check Catalog.
- Сейчас каждый новый гейт = новый workflow (паттерн «вдохновения» и в CI).

### Решение
1. **`ci-routes.json`** — один файл: «capability → какой скрипт запускать, какие роуты, какой browser».
```json
{
  "notes":        { "script": "node scripts/note-registry-core.js", "routes": ["gill-*"], "browser": false },
  "search-a11y":  { "script": "node scripts/search-a11y-contract.mjs", "routes": ["*"], "browser": "chromium" },
  "print-pdf":    { "script": "node scripts/print-paper.mjs", "routes": ["*"], "browser": "chromium+webkit" }
}
```
2. **Один workflow `project-gate.yml`** читает `ci-routes.json`, запускает нужные чеки, пишет `ci-summary.json` (duration, retries, passed-after-retry).
3. Новый чек = правка JSON (2 строки), НЕ новый workflow.
4. `dorny/paths-filter` определяет, какие capabilities затронуты (docs-only PR → почти ничего не гоняется).

**Почему «золото»:** 49 воркфлоу → 1 маршрутизатор + JSON. Убирает пролиферацию, флаки (единый runner), дубли setup/build. Это ровно рекомендация мастер-плана §8, но конкретизированная под проект.

## 6. ЗОЛОТОЕ РЕШЕНИЕ #6 — «Golden-дифф» главной (семантический, не пиксельный)

### Проблема
- 78 h-классов потеряно при Astro-миграции home; пиксельный visual-parity не ловит «секция пропала», если она убрана «аккуратно».

### Решение
1. Зафиксировать **структурный снимок** главной (порядок секций: nav → hero → sacred → quote → about → footer) в JSON.
2. На каждый PR, меняющий home: сравнить порядок/наличие секций со снимком; пропуск секции = fail (или owner-разрешение).
3. В отличие от пиксельного diff — ловит именно «секцию выкинули» и «класс переименовали», а не «шрифт на 1px другой».

**Почему «золото»:** дешёвый структурный контракт вместо хрупкого пиксельного; ловит класс «вдохновение убрало секцию».

## 8. Итог

Проект страдает не от недостатка проверок (их 49 workflow + миллионы assertions), а от **двух архитектурных дыр**:
1. **Референсы не машиночитаемы** → агенты «вдохновляются» → 74% классов расходятся → каскад.
2. **Контент не имеет единого AST-источника** → TTS/search/print живут на DOM-скрейпе → гонки и расхождения.

Обе дыры закрываются **6 золотыми решениями** (см. таблицу), которые не добавляют «ещё тесты», а **убирают целые классы ошибок и упрощают систему**. Это соответствует главному правилу проекта: «новый владелец обязан удалить старого» — AST-проекции удаляют DOM-скрейп, ci-routes удаляют 48 workflow, diff-canonical удаляет «вдохновение».
