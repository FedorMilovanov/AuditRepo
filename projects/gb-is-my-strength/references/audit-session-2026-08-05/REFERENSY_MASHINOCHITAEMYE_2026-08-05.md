# КАК СДЕЛАТЬ РЕФЕРЕНСЫ МАШИНОЧИТАЕМЫМИ — пошагово для твоего потока

**Дата:** 2026-08-05 · **Вопрос:** «Референсы агенты делают в чате, потом как? Они будут их куда-то подгружать?»

---

## 1. Главный ответ

**Референсы должны попадать в репозиторий В ТОТ МОМЕНТ, когда ты даёшь их агенту в чате — и превращаться в `contract/*.json` ДО того, как агент начнёт «вдохновляться».**

Сейчас поток такой:
```
ты даёшь HTML в чат → агент «смотрит» → делает по вдохновению → потом доправляет → main едет → вирус
```

Нужный поток:
```
ты даёшь HTML в чат → агент ПЕРВЫМ ДЕЛОМ кладёт его в docs/design-references/current/
  + генерирует contract JSON (requiredTokens/order/forbidden)
→ затем делает реализацию по контракту (не по памяти)
→ CI-гейт diff-canonical сверяет реализацию с контрактом
```

**Референсы НЕ «подгружаются откуда-то» — они уже у тебя в чате. Вопрос только в том, чтобы агент их СОХРАНЯЛ (в репо) и РАЗМЕЧАЛ (в JSON) до работы, а не после.**

---

## 2. Что именно «машиночитаемое» — три уровня

| Уровень | Что хранится | Формат | Кто создаёт |
|---|---|---|---|
| 1. RAW | твой HTML как есть | `.html` файл в `docs/design-references/current/` | агент сохраняет из чата (1:1, без изменений) |
| 2. CONTRACT | что ОБЯЗАТЕЛЬНО должно быть в реализации | `.json` (requiredTokens, order, forbidden, routes) | агент размечает (или ты, или автоматика) |
| 3. DIFF | сравнение реализации с контрактом | отчёт `.md`/консоль | скрипт `diff-canonical.mjs` |

**Ключевое:** контракт (уровень 2) — это не «описание стиля», а **список конкретных токенов/структуры**, которые машина умеет проверять: `data-gill-v16`, `__label`, `toc-part-item`, порядок `toc-sheet__handle → __head → __list`, запрет `hm-*`.

## 3. Твой реальный поток — пошагово (что делаешь ТЫ и что делает АГЕНТ)

### Шаг 0. Ты даёшь HTML в чат (как сейчас)
```
Ты: «Вот HTML мобильного бара, сделай так же: [вставка HTML]»
```

### Шаг 1. Агент ОБЯЗАН сначала сохранить и разметить (до кода)
```
Агент: «Принял. Сохраняю эталон и контракт:
  docs/design-references/current/gill-mobile-bar-ref.html   (HTML 1:1)
  contracts/gill-mobile-bar.json  (requiredTokens: [data-gill-v16, __label, toc-part-item, mobile-toc-btn],
                                   forbiddenTokens: [hm-*], routes: [gill-1..4, spravochnik, hermenevtika])
  Режим переноса: 1:1 REPLICA»
```

### Шаг 2. Агент реализует ПО КОНТРАКТУ (не по памяти)
- Каждый requiredToken обязан появиться в Astro-компоненте в том же порядке.
- Новые классы (`hm-*`, `gbs2-*`) — запрещены, если не согласованы с тобой.

### Шаг 3. Перед мерджем — `node scripts/diff-canonical.mjs --route gill-1`
```
CANONICAL: gill-mobile-bar-ref.html (12 required tokens)
PRESENT:   9/12 (data-gill-v16 ✓, __label ✓, toc-part-item ✓ ...)
MISSING:   3 (mobile-toc-btn, toc-sheet__list, ...)
NEW:       5 (gbs2-tocscroll, bar-progress-fill ...) — НУЖНО ТВОЁ РЕШЕНИЕ
VERDICT:   FAIL
```
- Если MISSING ≠ 0 или NEW ≠ 0 без твоего «ок» → PR не мержится.

### Шаг 4. Ты решаешь судьбу NEW-классов (1 клик)
```
Ты: «gbs2-tocscroll — ок, я одобрил, добавь в allowedTokens»
→ агент обновляет contract JSON (версия контракта +1)
```

## 4. Как это встроить в ЧАТ, а не в «какую-то систему»

Никакой «подгрузки извне» нет. Всё происходит внутри твоих чатов:

1. **Шаблон-промпт для агента** (вставь в начало каждого задания с референсом):
```md
У тебя есть референс (HTML/скриншот) в этом чате.
ПРАВИЛО 1: сначала сохрани его в docs/design-references/current/<name>.html (1:1, без изменений).
ПРАВИЛО 2: создай contracts/<name>.json (requiredTokens/order/forbidden/routes).
ПРАВИЛО 3: реализуй строго по контракту. Новые классы/структура — только после явного «ок» владельца.
ПРАВИЛО 4: перед PR запусти scripts/diff-canonical.mjs и приложи отчёт.
```
2. **`diff-canonical.mjs` живёт в репозитории** — любой агент его запускает, не «вдохновляется».
3. **Контракты накапливаются** в `contracts/*.json` — через месяц это библиотека «как выглядит мой проект», и новые агенты **читают её**, а не спрашивают тебя заново.

## 6. Кто «подгружает» и откуда — прямой ответ

- **Никто ничего не подгружает из интернета.** Референсы — твои, из чата.
- **Агент** кладёт их в `docs/design-references/current/` (сохраняет из чата).
- **Скрипт** `diff-canonical.mjs` читает контракты и сверяет реализацию.
- **Ты** решаешь судьбу «новых» классов (одобрить/запретить) — 1 сообщение.
- **CI** блокирует мердж, если расхождение не одобрено.

**Референс становится «машиночитаемым» не потому, что его куда-то грузят, а потому что из него в момент получения извлекают список токенов, которые машина может проверить.**
