Current main содержит **184 зарегистрированные сноски / 5 маршрутов**: 175 имеют видимое число, у 172 оно не совпадает с internal ordinal; 9 объяснений без числа не являются «потерянными номерами». Нормативный `docs/REFERENCE-TOOLTIP-CONTRACT.md`, Trigger semantics: **«Numbered Bible or academic notes preserve their visible number.»** Поэтому прежний closure «переписать все видимые номера внутренним ordinal» снят как чрезмерный. Нужно согласовать видимую авторскую метку с accessible name и endnote/backlink/print mapping, не нумеруя девять безномерных объяснений. Internal sequence может остаться технической. Для альтернативной публикационной перенумерации требуется явно согласованная policy/owner boundary, а не предположение аудитора.

## 2. Одна association-проблема и независимый mobile close-loop

Keyed/keyless glossary и reference controls используют один `initializeAnchor` без связи между trigger и portaled definition. **16** glossary focus/pointer states + **40** reference samples (10 routes ×4 profiles): native description пуст; у сносок той же страницы описание корректно. В **12** обратимых A/B один временный description link даёт 0→330/232/61 chars→0 после точного восстановления атрибутов. Это доказательство причины, не shipped fix и не полноценный AT verdict. Canonical ID теперь **`GBS-INLINE-TOOLTIP-DEFINITION-ASSOCIATION`**, прежний glossary ID — alias; BREF association не дублируется отдельной задачей.

Требование одинакового brief для каждого ключа снято как неустановленная обязательность. Различные authored и dictionary краткие тексты действительно существуют (два смысла/контекста), но различие строк само по себе не доказывает ошибку или необходимость переписывать авторскую прозу. Runtime явно предпочитает `plain(h) || z.brief`; contract не задаёт blanket literal equality. Semantic accuracy всех 130 определений и ручной cadence этой wave не оценивались. Отсутствие glossary index тоже не превращено в mandatory feature.

**`GBS-SCRIPTURE-AFFORDANCE-PLACEHOLDER-ONLY` retired, не FIXED.** Данные всё ещё не выдают verse text: 238 controls /10 routes имеют configured texts=0, каждый sampled popup показывает fallback. Но прежнее предположение «каждая кнопка обещает полный текст» не подтверждено: проверка visible/title/aria-label не нашла такого обещания, а popup реально раскрывает сокращение «Иер. 17:5–10» в «ИЕРЕМИЯ 17:5–10». Это reference info, не обязательно verse reader. Возможность полного текста/лучший fallback можно выбрать отдельно; corpus filling, снятие rights hold или 148 approvals не являются автоматически необходимой Product repair. Native `.bref` уже button: отсутствие явного `role` — не дефект. Реальный association fault остаётся в canonical root выше; не объявляем UI полностью здоровым. Повторное admission требует актуального обещания текста/сбоя разрешённой записи, не одного факта пустого corpus.

Новый независимый **`GBS-TOOLTIP-MOBILE-ESCAPE-REOPEN`** подтверждён в **8** mobile rich-tip состояниях (Light/Dark): Escape закрывает tip, затем `js/site-utils.js:476–479` возвращает фокус opener, а `article-tooltips.js:focus` открывает его заново. Desktop и plain mobile controls закрываются. Дополнительное 650ms наблюдение исключает объяснение «ещё идёт анимация»: trace true→false→true, trigger→Подробнее→trigger→Подробнее. Одноразовое capture-phase подавление только повторного focus-open оставляет закрытый tip и фокус на opener; удаление listener/reload возвращает дефект. Это A/B причины, не рекомендация глобально блокировать focus или отключить restoreFocus. #2183 уже меняет смежные owners, candidate UI не проверен; параллельный Product lane не создавался.
