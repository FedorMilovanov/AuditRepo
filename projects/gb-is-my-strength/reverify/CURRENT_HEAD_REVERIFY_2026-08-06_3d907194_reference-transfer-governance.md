### Explicit transfer modes

The policy distinguishes:

1. `exact-replica` — a real 1:1 target;
2. `adaptive-approved` — protected core with predeclared deviations;
3. `native-contract` — current native source/behavior is authoritative and historical HTML is evidence only;
4. `legacy-preserve` — intentionally independent surfaces that must not be genericized;
5. `performance-target` — measured future optimization, non-blocking until implemented;
6. `inventory` — evidence/counting only, never a Product gate.

An `exact-replica` claim now requires a committed immutable snapshot, a verified SHA-256 digest, named target owners, bounded structural/order checks and desktop/mobile visual review. Matching text, a few class names or approximate visual mood is not accepted as 1:1 evidence.

## D-22 current repair verdict

The historical favorite-link scheme/XSS half remained fixed. The Agent Arena reverify correctly found a narrower current residual: `normalizeImage()` accepted cross-origin HTTP(S) and protocol-relative URLs because it checked protocol but not origin.

Product PR #1076 adds the canonical boundary:

```js
if (!/^https?:$/.test(url.protocol)) return '';
if (url.origin !== location.origin) return '';
return url.href;
```

This preserves valid same-origin absolute and root-relative images and rejects cross-origin HTTP(S), protocol-relative, `data:`, `javascript:` and malformed values. A bounded permanent marker contract protects the exact normalizer sequence.
