# Reverify — gb-is-my-strength

`reverify/` stores significant checks performed for a selected decision or work package.

Create a separate reverify document when it adds lasting value:

- disputed disposition;
- major root-cause correction;
- security, rights, data-loss or production claim;
- system fix absorbing many findings;
- important live/artifact witness;
- complex current-check wave whose evidence should remain independently readable.

Do **not** create a document solely because:

- Product HEAD changed;
- an unrelated PR merged;
- a previously closed owner acquired a new blob SHA;
- one ordinary finding was fixed with an already permanent Product regression test.

A reverify document is tied to its explicit anchor and question. It remains useful historical evidence after newer Product commits.

Routine local closure may link directly to the Product PR/contract from `verified/CLOSURE_LEDGER.md`.
