## Durable invariants

- generic application startup performs zero community reads;
- target subscriptions have explicit `passive`, `summary` and `full` modes;
- a detail target reads one aggregate row and a bounded first comment page;
- comments use stable `(created_at DESC, id DESC)` cursor pagination with equal-timestamp tie breaking;
- `/ratings` reads bounded aggregate rows for known poet ids only and never downloads raw rating rows or comment bodies;
- public remote corpora remain ephemeral and never enter the persisted v3 browser envelope;
- v2 migration drops cached public rows while retaining pending writes and the visitor's own ratings;
- optimistic ratings, comments and helpful votes overlay server aggregates/pages without double counting;
- outbox retry, offline state, cooldowns, helpful state, cross-tab notifications and storage-failure honesty remain production contracts;
- aggregate schema rollout is additive; a bounded detail-target fallback remains available while the leaderboard fails closed rather than fanning out raw reads;
- backend RPC id validation accepts the UUID-shaped ids generated by the client and the server comment limit matches the client at 2,000 characters;
- desktop request topology is retained in Manual Browser QA, while a permanent exact-head mobile contract proves the same boundaries on Android Chrome and iPhone Safari/WebKit;
- a failed helpful write for a remote comment stays optimistic and queued across reload while `localSnapshot.comments` remains empty.
